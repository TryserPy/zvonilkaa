# Развёртывание на хостинге

Туннели бесплатных сервисов рвутся, а некоторые провайдеры режут их целиком.
Хостинг снимает вопрос: постоянный адрес, настоящий сертификат, ничего не
блокируется, компьютер можно выключать.

Проект без зависимостей, поэтому разворачивается почти на чём угодно. Ниже —
пошагово для Render, у которого бесплатный тариф жив и поддерживает
WebSocket. В конце — вариант через Docker для любой другой площадки.

---

## Что попадёт на сервер

Только сигналинг: сервер сводит двоих в комнате и отходит в сторону. Видео и
звук по-прежнему идут напрямую между собеседниками и шифруются DTLS-SRTP —
хостинг физически не может их прослушать. Нагрузка на сервер — несколько
килобайт на установку связи.

---

## Render

### 1. Положите проект в репозиторий

Render разворачивает из GitHub, так что проект надо туда залить целиком —
**вместе с папками `lib` и `public`**. Это главное место, где всё ломается:
если папка не доедет, сборка упадёт с сообщением вроде
`"/public": not found`.

**Способ первый, надёжный — GitHub Desktop.** Подходит, если не хочется
возиться с командной строкой.

1. Поставьте [GitHub Desktop](https://desktop.github.com) и войдите в свой
   аккаунт.
2. **File → Add local repository**, укажите папку `zvonilka`. Программа
   предложит создать репозиторий — соглашайтесь.
3. Внизу слева впишите любое описание, нажмите **Commit to main**, затем
   **Publish repository**. Приватный или публичный — на ваш выбор.

**Способ второй — командная строка**, если git уже установлен:

```bash
cd путь\к\zvonilka
git init
git add .
git commit -m "Звонилка"
```

Дальше создайте пустой репозиторий на github.com и выполните то, что он
покажет:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/zvonilka.git
git branch -M main
git push -u origin main
```

Оба способа уважают `.gitignore`, поэтому логи, сертификаты и
`tools/cloudflared.exe` (а это 55 МБ) в репозиторий не попадут.

**Загрузка через сайт GitHub не рекомендуется.** Кнопка «Upload files» легко
теряет вложенные папки — именно так `public` и остаётся за бортом. А если
перетащить папку целиком, загрузка упадёт на `cloudflared.exe`: у веб-формы
ограничение 25 МБ на файл.

### Проверьте, что всё доехало

Откройте репозиторий на GitHub. Внутри должны быть видны:

```
lib/       ws.js, selfsigned.js
public/    index.html, app.js, styles.css, icon.svg, manifest.webmanifest
server.js
package.json
Dockerfile
render.yaml
```

Если папки `public` нет — сборка гарантированно упадёт. Перезалейте одним из
двух способов выше.

### 2. Создайте сервис

1. Зарегистрируйтесь на [render.com](https://render.com) — вход через GitHub.
2. **New → Blueprint**, выберите свой репозиторий.
   Render найдёт `render.yaml` и всё настроит сам: тариф free, регион
   Франкфурт, команда запуска, проверка здоровья.
3. Нажмите **Apply** и подождите пару минут.

Если Blueprint по какой-то причине не подхватился, сделайте **New → Web
Service** руками:

| Поле | Значение |
|---|---|
| Runtime | Node |
| Build Command | оставить пустым |
| Start Command | `node server.js` |
| Instance Type | Free |
| Health Check Path | `/api/health` |

Переменную `PORT` задавать не надо — Render передаёт её сам, сервер её
подхватывает.

### 3. Готово

Render выдаст адрес вида `https://zvonilka-xxxx.onrender.com`. Это и есть
постоянная ссылка: открываете, создаёте звонок, отправляете собеседнику
ссылку на комнату.

### Что нужно знать про бесплатный тариф

* **750 часов в месяц** на весь аккаунт. Одному сервису, работающему
  круглосуточно, нужно около 730 — впритык, но хватает.
* **Засыпает после 15 минут без запросов.** Первое открытие после сна
  занимает около минуты — браузер покажет страницу загрузки. Поэтому лучше
  сначала открыть сайт самому, дождаться загрузки и только потом отправлять
  ссылку собеседнику.
* Диск не сохраняется между перезапусками. Звонилке он и не нужен: комнаты
  живут в памяти, никаких данных не хранится.

## Любая другая площадка — через Docker

В проекте лежит `Dockerfile`. Он подойдёт для Railway, Coolify, собственного
VPS и всего, что умеет запускать контейнеры:

```bash
docker build -t zvonilka .
docker run -p 3000:3000 zvonilka
```

Сборка сама проверяет, что все файлы на месте, и падает с понятным
сообщением, если в репозиторий заехало не всё.

Что важно на любой площадке:

* сервер слушает порт из переменной `PORT`, по умолчанию 3000;
* нужен HTTPS — почти везде он даётся автоматически;
* WebSocket-соединения на пути `/ws` должны проходить (Render, Railway и
  обычный nginx это умеют, отдельной настройки не требуется).

На своём VPS с nginx перед приложением добавьте в секцию `location /`:

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 3600s;
```

Без этих строк обычные страницы откроются, а звонок не соединится: сигналинг
идёт по WebSocket.

## Если звонок не соединяется

Сайт открывается, комната создаётся, но собеседники не видят друг друга —
значит, прямое соединение между ними не устанавливается. Так бывает, когда
оба сидят за строгим NAT: мобильный интернет, корпоративная сеть, провайдер с
общим IP.

Проверить просто: в звонке откройте статистику (кнопка с пингом), строка
«Маршрут» покажет, что происходит.

Лечится TURN-сервером — ретранслятором для таких случаев. Поднимается
[coturn](https://github.com/coturn/coturn) на любом VPS, адрес передаётся
переменными окружения:

```
TURN_URL=turn:turn.example.com:3478
TURN_USERNAME=user
TURN_PASSWORD=secret
```

На Render это **Environment → Add Environment Variable**. В `render.yaml`
соответствующие строки уже заготовлены, надо только раскомментировать.

Медиапоток через TURN остаётся зашифрованным: ретранслятор пересылает пакеты,
не имея ключей.

## Обновление

Render следит за веткой `main`. Достаточно отправить изменения:

```bash
git add .
git commit -m "что изменилось"
git push
```

Через минуту-другую новая версия будет на сайте.
